# 日常菜谱库实施合同

用户于 2026-10-03 授权继续功能完善，暂缓 APK 打包与 Android 验收。继承外部执行文件的产品基线，打包优先顺序已被替代。

## 当前模块

目标：不使用 AI，也能创建、保存、搜索、查看和编辑一份可照着做的菜谱。

范围：已有 Vite 客户端；首页/我的菜谱/设置；菜名、实际食材用量、完整步骤、提前准备、关键事项、手动耗时/份数、备注、本地封面和步骤图；五秒删除撤销；轻量修改快照存储入口。

约束：只有菜名可保存；未知值保留空；不将提前准备自动相加；不缩放用量；允许重名；搜索菜名/食材；耗时边界 30/60 分钟不重叠；删除撤销期保留所有关联数据。核心不联网、不登录。已有 APK-0 数据通过 SQLite v1→v2 增量迁移保留。

存储：Android 扩展同一个 SQLite，文件保存到私有持久目录；本地 Web 开发预览适配已有 IndexedDB `localRecipes`/`media`，不创建新业务主库。相同领域模型和 Repository 接口，浏览器验证不等同原生验证。历史快照使用 JSON 合理记录旧/新值，正式食材/步骤在 SQLite 中规范化。

不处理：APK 构建/发布、云数据、AI、做过记录与历史界面、逐步烹饪、完整备份恢复、推荐、收藏、购物、计划或计时器。媒体文件保守保留以避免破坏历史引用，回收机制后续完善。

## 实施与验收

1. 先写迁移、原子保存、字段校验、搜索/耗时和删除撤销测试，再扩展 Repository。
2. 本地媒体适配器；错误不阻塞文字，上传失败不显示保存成功。
3. 同一界面用于 Vite Web 开发预览和后续 Android；表单、详情、卡片、三个导航入口及未保存退出保护。
4. 验证只有菜名、完整菜谱、编辑刷新、图片刷新、非法输入、写入失败、字面搜索、耗时边界、删除撤销和 v1 数据迁移。
5. 实际执行相关/全量测试、类型、Lint、Vite 构建及浏览器手机/桌面回归；不运行 APK 打包或声称 Android 新版已验收。
6. 同步事实源、本地提交，模块验收点暂停。无推送或线上部署。
