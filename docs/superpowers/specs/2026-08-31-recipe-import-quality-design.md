# 食序 ORDINE AI 导入质量增强设计

**日期：** 2026-08-31

**状态：** 已确认，实施计划已完成

**适用范围：** 菜谱来源导入、AI 结构化草稿、导入审核与失败恢复；本规格只包含模块 10，不增加新的 AI 服务商、数据库表或远程任务系统

## 1. 目标

用户从公开网页、视频链接、粘贴文案或截图生成菜谱草稿后，应当清楚知道哪些内容来自来源、哪些是 AI 推断、哪些仍然缺失。食材数量、文字用量、单位、调料分组、火候、计时、提前准备、分类和标签都需要进入同一套审核流程。

关键烹饪信息不明确时，系统必须保持为空并显示检查提示，不允许 AI 根据常识静默补全。存在推断或缺失内容的草稿只有在用户明确确认已经检查后才能保存。

本模块继续使用 Qwen 3.8 Flash 作为默认模型，保留当前“自动推荐、只用 Qwen、只用 Gemini”的选择能力。现有 `recipe_import_jobs.draft` 和 `warnings` JSON 足够承载审核元数据，不新增数据库表或迁移。

## 2. 非目标

- 不新增 AI 服务商、向量数据库、OCR 服务或内容抓取服务。
- 不修改 Qwen 优先、Gemini 可选回退的模型路由规则。
- 不保证绕过需要登录、验证码、Cookie 或应用内打开的平台访问限制。
- 不自动创建分类和标签；仍只匹配已有分类与标签，未匹配内容由用户决定。
- 不自动补齐营养数据、菜谱背景知识、替代食材或来源没有提到的烹饪技巧。
- 不建立审核记录数据库表，不提供审核历史、团队审批或管理员后台。
- 不把 AI 原始响应、完整提示词、API 密钥或用户私有来源写入日志。
- 不调整现有 Supabase RLS、Storage bucket 或 Production 环境变量。

## 3. 现状与主要缺口

当前导入链路已经具备：

- URL、文案和图片三种输入方式。
- Qwen 3.8 Flash、Gemini 和自动回退选择。
- 食材数字数量、文字用量、单位、调料分组、火候、计时和提前准备字段。
- `recipe_import_jobs.draft` 草稿 JSON 与独立 `warnings` JSON。
- AI 输出 Zod 校验、来源抓取安全检查和导入任务私有访问。

当前主要缺口是：

1. `warnings` 只有自然语言，不能稳定定位到具体字段。
2. 编辑页无法区分来源明确、AI 推断和缺失内容。
3. 提示只要求用户检查，没有可验证的确认动作，点击“保存菜谱”即可直接保存。
4. 失败页只显示统一文案，并且失败任务加载后会自动再次请求，缺少明确的手动重试控制。
5. 字段归一化虽已处理常见数量文本，但模型输出契约没有要求为每个重点字段提供审核状态。

## 4. 方案选择

采用“草稿内结构化字段检查清单”方案。`recipe_import_jobs.draft` 增加审核元数据，`warnings` 继续保存面向用户的总体提示。

未采用只根据空值和 `warnings` 推导状态的方案，因为它无法区分来源明确与 AI 推断，也无法稳定关联具体食材或步骤。

未采用新增审核表或新增数据库列的方案，因为这些元数据只在导入确认阶段使用，菜谱保存后不需要长期查询。把它们留在现有临时草稿 JSON 中改动更小，也符合导入任务到期清理的现有生命周期。

## 5. 草稿与字段检查模型

### 5.1 字段状态

字段状态固定为：

```ts
type RecipeImportFieldStatus = "explicit" | "inferred" | "missing";
```

- `explicit`：AI 判断该值在文字、画面或视频中被明确表达。
- `inferred`：AI 根据上下文整理或归类，来源没有直接给出同等明确的信息。
- `missing`：来源无法确认，草稿对应字段必须保持 `null`、空数组或空字符串允许的空态。

界面文案分别为“来源明确”“AI 推断”“缺失待确认”。文案必须说明这是 AI 对来源的识别结果，不把 `explicit` 描述成经过人工或事实核验。

### 5.2 检查项结构

草稿增加：

```ts
type RecipeImportFieldCheck = {
  path: string;
  status: RecipeImportFieldStatus;
  label: string;
  message: string | null;
};

type RecipeImportReview = {
  fieldChecks: RecipeImportFieldCheck[];
  requiresConfirmation: boolean;
  confirmedAt: string | null;
};
```

`path` 使用受控的稳定路径，例如：

- `title`
- `baseServings`
- `prepMinutes`
- `cookMinutes`
- `suggestedCategoryName`
- `suggestedTagNames`
- `ingredients.0.quantity`
- `ingredients.0.quantityText`
- `ingredients.0.unit`
- `ingredients.0.groupType`
- `steps.0.heatLevel`
- `steps.0.timerSeconds`
- `steps.0.ingredientNames`
- `preparations.0.leadTimeMinutes`
- `preparations.0.timingText`

`label` 是可读名称，例如“鱼片的用量”“第 2 步火候”。`message` 只说明为什么需要检查，不保存长篇来源原文或模型推理过程。

检查项最多 300 条；`path`、`label` 和 `message` 都有长度限制。重复路径在服务端归一化时合并，以最保守的状态为准：`missing` 高于 `inferred`，`inferred` 高于 `explicit`。

### 5.3 模型输出与持久化草稿分离

模型输出 schema 不接受 `confirmedAt`。AI 只能返回结构化菜谱内容、字段状态和警告；用户确认时间只能由认证后的 Server Action 写入。

持久化草稿 schema 在模型输出基础上增加：

- 归一化后的字段检查清单。
- 服务端计算的 `requiresConfirmation`。
- 服务端写入的 `confirmedAt`。

旧导入任务没有 `review` 时继续能够读取。兼容层根据空字段与既有 `warnings` 生成保守检查项，并将 `requiresConfirmation` 设为 `true`，避免旧任务绕过审核。

## 6. AI 提取与确定性归一化

### 6.1 提示词规则

Qwen 与 Gemini 继续共用同一套提示词和 Zod schema。提示词补充以下约束：

- 数字数量只放入 `quantity`，独立单位放入 `unit`。
- “少许、适量、一包、大量”等完整保留在 `quantityText`，不强行换算数字。
- 调料必须优先进入 `seasoning` 分组；无法确定才进入 `other`。
- 每个步骤只在来源明确时填写 `heatLevel` 和 `timerSeconds`。
- “炸五分钟”换算为 `300` 秒；没有时间不得根据常识补写。
- 腌制、浸泡、解冻、醒发、静置和回温进入 `preparations`。
- 精确提前时间进入 `leadTimeMinutes`；“提前一晚”“泡至变软”进入 `timingText`。
- 分类与标签允许根据内容推断，但必须标记为 `inferred`。
- 重点字段必须返回对应检查项；缺失值必须使用 `missing`，不能省略检查项。

### 6.2 服务端归一化

模型输出通过 Zod 后，再执行确定性质量整理：

1. 继续应用当前的嵌入数量拆分和来源文字数量恢复规则。
2. 对所有重点字段补齐检查项，不能依赖模型是否完整返回。
3. 对值为空的重点字段强制改为 `missing`。
4. 对关键数值标记为 `inferred` 时清空对应值，避免把推测数字带入草稿。
5. 对分类和标签的 `inferred` 值保留，但在审核面板明确显示。
6. 将未关联到真实字段的路径丢弃，不允许任意字符串控制界面。
7. 根据是否存在 `inferred` 或 `missing` 计算 `requiresConfirmation`。
8. 生成去重后的总体 `warnings`，同时写入任务的 `draft` 和 `warnings`。

关键数值包括食材 `quantity`、步骤 `timerSeconds`、准备 `leadTimeMinutes`、总准备时间和总烹饪时间。文字用量、文字时间和火候无法确认时保持为空。

## 7. 审核界面

### 7.1 审核摘要

AI 整理成功后，菜谱编辑器上方新增导入审核面板：

- 显示“来源明确、AI 推断、缺失待确认”的数量汇总。
- 按“基础信息、食材与调料、步骤与火候、提前准备、分类与标签”分组。
- 每条提示显示字段名称、状态和简短原因。
- `explicit` 默认折叠，只突出 `inferred` 和 `missing`。
- 没有不确定项时显示“未发现需要特别确认的字段”，不要求额外勾选。

第一版不在每个输入框旁增加复杂图标，也不实现字段级跳转和自动判定“用户是否修改过”。用户可以在同一页面修改菜谱字段，再回到审核面板确认。

### 7.2 确认门禁

存在 `inferred` 或 `missing` 时：

- 审核面板显示复选框“我已检查以上 AI 推断和缺失内容”。
- 未勾选时“保存菜谱”按钮仍可聚焦，但提交后必须阻止保存，并把焦点移回审核提示。
- 勾选后，客户端先调用确认 Server Action，由服务端验证任务属于当前用户、状态为 `review`、草稿仍然有效，再写入 `confirmedAt`。
- 确认成功后才调用现有菜谱保存动作。
- `finalizeRecipeImportAction` 再次验证：如果任务需要确认，则必须存在服务端写入的 `confirmedAt`；否则拒绝完成导入。

没有不确定项时，`requiresConfirmation=false`，用户可直接保存。

确认只表示用户已经看过提示，不代表内容客观正确。用户修改编辑器内容后不自动清除确认状态，因为第一版没有把编辑器字段逐项同步回临时草稿；保存动作仍使用经过当前表单校验的最终值。

### 7.3 保存失败的一致性

现有流程会先保存菜谱，再完成导入任务。第一版保持该流程，避免重构整个菜谱保存 API。若菜谱已保存但导入完成动作失败：

- 不删除已经保存的菜谱。
- 编辑器显示明确提示，并允许重试完成导入标记。
- 完成动作保持幂等；同一任务和菜谱重复调用不会重复创建来源。

确认门禁在菜谱保存前执行，因此不会出现未确认草稿先创建菜谱的情况。

## 8. 失败原因与恢复

失败页面根据 `error_code` 显示具体、非技术化原因：

| 错误码 | 用户提示 | 可重试 |
| --- | --- | --- |
| `unsafe_url` | 该链接不符合安全访问要求 | 否 |
| `source_unreadable` | 页面内容无法公开读取，可能需要登录或在应用内打开 | 是 |
| `source_too_large` | 页面内容过大，无法直接整理 | 否 |
| `ai_rate_limited` | AI 请求过于频繁，请稍后再试 | 是 |
| `ai_unauthorized` | AI 服务配置不可用 | 是 |
| `ai_unavailable` | AI 服务暂时不可用 | 是 |
| `invalid_ai_output` | AI 返回内容不完整，未生成可审核草稿 | 是 |
| `processing_failed` | 导入处理失败 | 是 |

失败任务页面不再自动重新提交。可重试错误显示“重新尝试”按钮，点击后只发起一次处理请求，并显示进行中状态，防止重复点击。

所有失败页面都提供：

- “粘贴文案”入口。
- “上传截图”入口。
- 返回导入首页入口。

不安全链接和内容过大不显示对同一任务的重试按钮，避免无意义循环。重试仍使用任务原先保存的模型选择，不静默切换用户选择。

## 9. 模块边界与文件职责

现有 `src/features/recipe-imports/` 继续作为唯一功能目录，新增两个小型边界：

- `quality-review.ts`：检查项路径白名单、状态归一化、关键值清空、旧草稿兼容和 `requiresConfirmation` 计算。
- `components/import-review-panel.tsx`：审核摘要、分组提示和确认复选框。

主要现有文件职责调整：

- `schemas.ts`：区分模型输出草稿和持久化审核草稿 schema。
- `recipe-ai-shared.ts`：扩展提示词并在输出解析后调用质量归一化。
- `process.ts`：把审核草稿和警告写入任务，保持现有提供商选择。
- `queries.ts`：兼容读取旧草稿与新审核草稿。
- `actions.ts`：新增确认动作，完成导入时验证确认状态。
- 导入详情页：在菜谱编辑器上方加载审核面板。
- `recipe-editor.tsx`：只增加可选的导入审核门禁接口，不改变普通新建和编辑菜谱流程。
- `import-progress.tsx`：按错误码展示原因和显式重试。

不修改普通菜谱数据模型，不把导入审核类型加入 `RecipeSaveInput`。

## 10. 数据流

### 10.1 成功导入

```text
来源抓取或图片签名
→ Qwen/Gemini 返回结构化草稿与字段状态
→ Zod 校验
→ 服务端质量归一化并清除不可靠关键值
→ 生成 review.fieldChecks、requiresConfirmation 和 warnings
→ 写入 recipe_import_jobs.draft / warnings
→ 显示审核面板和菜谱编辑器
→ 用户修改草稿并确认不确定项
→ 服务端记录 confirmedAt
→ 保存菜谱
→ 完成导入任务并保存来源
```

### 10.2 失败导入

```text
抓取或 AI 处理失败
→ 映射稳定 error_code
→ 任务状态变为 failed
→ 页面显示具体原因
→ 用户选择单次重试、粘贴文案或上传截图
```

## 11. 权限与安全

- 所有确认和完成动作都使用 Supabase Auth 当前用户，并同时按 `id` 和 `user_id` 查询任务。
- 客户端不能提交或覆盖 `confirmedAt`。
- 任务不是 `review` 状态、草稿缺失或已过期时不能确认。
- `fieldChecks.path` 只接受受控路径，避免把任意模型字符串用于 DOM 选择器、路由或数据库字段。
- 错误响应只返回稳定错误码和用户文案，不返回提供商响应体。
- 日志只记录任务 ID、阶段、服务商和稳定错误码，不记录 API 密钥、来源全文、字段提示或模型原始输出。
- 本模块不新增表；现有 `recipe_import_jobs` 强制 RLS 和用户所有权策略继续生效。

## 12. 兼容性与生命周期

- 旧草稿没有 `review` 时由查询兼容层生成保守审核信息。
- 新草稿的额外 JSON 字段不影响数据库 schema、RLS 或已有任务清理。
- 保存完成后继续清空临时 `draft` 和来源正文，不把审核元数据复制进正式菜谱。
- 任务过期和用户删除任务时继续沿用现有图片清理逻辑。
- 普通新建、普通编辑和旧菜谱保存不显示审核面板，也不经过确认动作。
- Qwen、Gemini 和自动推荐三种模型选择必须生成相同版本的草稿结构。

## 13. 测试与验收标准

### 13.1 Schema 与质量归一化

- 合法的新草稿、旧草稿兼容、非法状态、非法路径、重复路径和超限检查项。
- 空值强制变为 `missing`。
- 推断的关键数值被清空并产生警告。
- 数字数量、文字用量和单位保持互斥且不丢失。
- 调料分组、火候、计时、提前准备、分类和标签均生成检查项。
- `requiresConfirmation` 只在存在 `inferred` 或 `missing` 时为 `true`。

### 13.2 AI 提取与处理

- Qwen 3.8 Flash 保持默认模型。
- 自动模式仍是 Qwen 优先、可恢复失败时回退 Gemini。
- 三种模型选择返回一致的审核草稿。
- 模型遗漏检查项时服务端可以补齐。
- 非法 AI 输出进入 `invalid_ai_output`，不产生可保存草稿。
- 任务同时写入审核草稿和去重警告。

### 13.3 确认与权限

- 无不确定项可以直接保存。
- 有不确定项且未确认时，客户端不调用菜谱保存动作。
- 确认动作只允许任务所有者执行。
- 客户端伪造确认时间无效。
- `finalizeRecipeImportAction` 拒绝未确认的任务。
- 确认、保存和完成动作重复调用保持幂等。

### 13.4 UI 与错误恢复

- 审核面板正确显示三类数量、分组和状态文案。
- 移动端 360、390、430 px 和桌面端可阅读、可键盘操作。
- 未确认提交时焦点回到审核提示，错误不只依靠颜色表达。
- 失败页针对各错误码显示正确原因。
- 失败页面加载时不自动重试。
- 可重试错误只在用户点击后请求一次，并禁用重复点击。
- 粘贴文案、上传截图和返回入口始终可用。

### 13.5 回归与发布门禁

- 运行 recipe-imports、recipes 编辑器、Server Action 和 API Route 相关测试。
- 运行完整 TypeScript 检查、ESLint、Vitest 和 Production build。
- 检查 git diff、未跟踪文件和敏感信息。
- Preview 回归 URL、文案、单图和多图导入。
- 分别验证“自动推荐”“只用 Qwen”和配置可用时的“只用 Gemini”。
- 功能分支验收通过后暂停；Production 发布需要单独明确确认。

## 14. 人工验收场景

1. 导入包含“豆瓣酱 2 勺、干锅酱一包、盐少许”的文案，数字数量、单位和文字用量分别正确保存。
2. 来源没有鱼片重量，草稿用量保持为空，审核面板显示“鱼片的用量：缺失待确认”。
3. 来源写“炸五分钟”，步骤计时为 300 秒并标记来源明确；没有火候时火候为空。
4. 来源写“牛肉提前腌制 30 分钟”，生成提前准备和精确提前时间；“绿豆提前一晚浸泡”只保留文字时间。
5. AI 建议“干锅”“高蛋白”标签时标记为 AI 推断，不自动创建不存在的标签。
6. 未勾选审核确认直接保存，页面阻止提交并聚焦提示；勾选后可以保存。
7. 使用另一个用户访问或确认该导入任务，返回不存在或无权限，不能读取草稿。
8. 模拟限流后页面显示具体原因，不自动重试；点击一次“重新尝试”只发出一次请求。
9. 不可公开读取的小红书链接失败后，可以直接切换到粘贴文案或上传截图。
