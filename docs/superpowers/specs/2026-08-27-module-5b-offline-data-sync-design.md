# 食序 ORDINE：Module 5B 离线数据与恢复同步设计规格

- 日期：2026-08-27
- 状态：用户已确认（2026-08-27）
- 所属项目：食序 ORDINE
- 所属模块：Module 5B（离线数据与恢复同步）
- 目标分支：`feat/recipe-app-shopping`

## 1. 背景

Module 5A 已完成 PWA 安装、公共离线页和安全更新流程，但当前离线页不包含私人数据。用户确认 Module 5B 必须支持“关闭应用后，断网重新打开仍能使用”。

现有受保护页面主要由 Next.js Server Components 和 Supabase Cookie 会话驱动。若直接缓存登录后的 HTML、RSC、API 或任意 Next.js 运行资源，会带来私人数据泄漏、新旧页面与样式混用以及更新循环风险。因此，本模块采用独立公开离线壳与 IndexedDB 私有快照分离的方案。

## 2. 目标

1. 已登录用户在线使用后，可在完全关闭应用、断网并重新打开时查看最近菜谱和当前购物清单。
2. 最近打开的 10 道菜谱可以离线查看详情并进入分步烹饪。
3. 当前购物清单可以离线查看、勾选和取消勾选。
4. 离线勾选操作在恢复网络后自动、安全、可重复地同步。
5. 退出登录时清除该设备上的全部私人离线数据和待同步操作。
6. 不缓存登录后页面、API 响应、Supabase 响应或任意用户私人网络响应。
7. 保持 Module 5A 的“用户确认更新后才接管、接管后只刷新一次”行为。

## 3. 非目标

- 不支持离线创建或编辑菜谱。
- 不支持离线新增、编辑、删除、排序、清空或重新生成购物清单。
- 不支持离线收藏、搜索全量菜谱或修改设置。
- 不在首版缓存菜谱封面和步骤图片；离线时使用占位图，避免大体积 Blob、配额和私人图片生命周期复杂度。
- 不实现跨设备实时协同、CRDT 或复杂合并算法。
- 不修改现有数据库结构和业务 API 范围，除非编码阶段验证发现现有约束无法满足安全同步；若出现该情况必须暂停并重新提交数据库方案。

## 4. 已确认约束

- 应用只考虑个人使用，不包含家庭成员或共享空间。
- Supabase Auth 仍是唯一身份来源；IndexedDB 不是认证机制。
- 菜谱离线快照只读。
- 购物清单离线只允许切换 `isChecked`。
- 同一个条目连续离线操作只保留最后目标状态。
- 冲突规则为“服务器最后实际接收到的有效状态生效”，同步后再用服务器结果刷新本地快照。
- 无法同步时保留队列并提示用户，不静默丢弃。

## 5. 方案选择

### 5.1 采用方案：公开离线壳 + IndexedDB 私有快照

职责分离如下：

- Cache Storage：只保存公开、版本化的离线壳及其精确依赖资源。
- IndexedDB：保存当前设备、当前账号的私人菜谱快照、购物清单快照和待同步队列。
- Service Worker：负责冷启动路由、公开离线壳版本切换和网络恢复入口，不读取或写入私人业务数据。
- React 客户端：在线时写入快照，离线壳中读取快照，恢复联网后执行同步。
- Server Action：重新验证登录用户、清单所有权和当前有效清单，再执行幂等目标状态更新。

### 5.2 未采用方案

1. 缓存完整 Next.js 私人页面：会缓存用户 HTML/RSC，并显著增加新旧资源不一致风险。
2. 维护第二套纯 JavaScript 静态应用：冷启动简单，但与 TypeScript 规范冲突，且会复制 UI、类型和业务展示逻辑。
3. 引入完整离线同步框架：当前仅有只读快照和单字段队列，收益不足以覆盖依赖体积和长期维护成本。

## 6. 总体架构

### 6.1 在线模式

1. 服务器照常鉴权并返回菜谱或购物清单。
2. 客户端在页面稳定渲染后异步写入 IndexedDB，不阻塞首屏和点击响应。
3. 菜谱按最近打开时间保留最多 10 条；超过上限时删除最旧快照。
4. 当前购物清单使用单份覆盖式快照。
5. `PwaRuntime` 监听联网状态；恢复网络时触发一次队列同步。

### 6.2 离线冷启动

1. 用户从 PWA 启动地址或历史链接进入受支持的私人路径。
2. Service Worker 网络请求失败后，把受支持路径重定向到公开的 `/offline/app`，并在查询参数中保留原目标路径。
3. `/offline/app` 从当前版本公开缓存中加载，不依赖登录 Cookie 或网络请求。
4. 离线壳根据目标路径和 IndexedDB 快照显示菜谱列表、菜谱详情、分步烹饪或当前购物清单。
5. 不支持的路径继续显示现有 `/offline.html` 通用提示页。

### 6.3 恢复联网

1. 离线壳或在线应用收到 `online` 事件后，先显示“正在同步”。
2. 同步器读取当前账号待同步队列，并按入队时间顺序逐条提交。
3. 每项提交的是目标布尔状态，不是“反转一次”，因此重复提交仍是幂等的。
4. 成功后删除对应队列项，并获取服务器当前购物清单刷新本地快照。
5. 所有项目完成后显示一次成功反馈；失败项目继续保留。
6. 如果恢复联网时 Supabase 会话已失效，停止同步、保留队列并引导重新登录。

## 7. 公开离线壳与 Service Worker

### 7.1 离线壳

- 新增公开路由 `/offline/app`，使用 TypeScript/React 实现。
- 路由不读取 Supabase、不输出用户数据、不要求登录，可安全预缓存。
- 只提供离线数据选择和展示能力，不复制在线编辑功能。
- 离线壳继续复用现有设计变量和可访问性规范。
- 需要在认证中间件公开路径允许列表中明确放行。

### 7.2 精确资源缓存

Service Worker 安装时：

1. 请求 `/offline/app` 的公开 HTML。
2. 从 HTML 中提取该页面实际引用的同源 `/_next/static/` 脚本和样式地址。
3. 只把该 HTML、提取出的精确构建资源、Manifest、图标和 `/offline.html` 写入带部署版本的缓存。
4. 任一核心壳资源预缓存失败时，本次 Worker 不进入可更新状态，旧版本继续工作。

这里缓存的 Next.js 文件仅是公开离线壳的精确版本依赖，不包含私人页面、任意运行时请求或跨版本长期缓存。

### 7.3 更新一致性

- 缓存名继续绑定 Vercel Commit SHA 或显式 PWA 版本。
- 新 Worker 安装后保持 waiting，用户点击“立即更新”才执行 `SKIP_WAITING`。
- 激活后删除旧版本公开壳缓存并 `clients.claim()`。
- `controllerchange` 仍只刷新一次。
- HTML、JS 和 CSS 在同一个版本缓存中原子切换，避免新页面配旧样式。

### 7.4 路由范围

离线壳支持：

- `/recipes`
- `/recipes/:recipeId`
- `/recipes/:recipeId/cook`
- `/shopping`

登录、设置、编辑、创建和其他未知路径不读取私人快照，统一回退到通用离线提示。

## 8. IndexedDB 数据设计

采用小型、成熟的 `idb` Promise 封装，避免手写大量 IndexedDB 事件与事务样板；不引入大型离线框架。

数据库名称：`ordine-offline-v1`

### 8.1 `profiles` 存储

记录本设备最后一次成功在线鉴权的用户标识，只用于选择 IndexedDB 命名空间：

```ts
type OfflineProfile = {
  userId: string;
  lastAuthenticatedAt: string;
};
```

不得存储访问令牌、刷新令牌、Cookie、邮箱验证码或其他认证凭据。

### 8.2 `recipes` 存储

键：`[userId, recipeId]`

```ts
type OfflineRecipeSnapshot = {
  userId: string;
  recipeId: string;
  cachedAt: string;
  lastOpenedAt: string;
  dataVersion: 1;
  recipe: OfflineRecipeDetail;
};
```

`OfflineRecipeDetail` 只保留离线详情和烹饪所需字段：标题、备注、份数、时间、标签、食材、步骤、步骤食材关联、计时信息和排序。网络签名图片 URL 与 Storage 路径不写入首版离线快照。

### 8.3 `shoppingSnapshots` 存储

键：`userId`

```ts
type OfflineShoppingSnapshot = {
  userId: string;
  listId: string;
  cachedAt: string;
  serverUpdatedAt: string;
  dataVersion: 1;
  list: OfflineShoppingList;
};
```

只保留当前活动清单及展示所需来源信息。在线生成新清单后覆盖旧快照，并清理旧清单对应的无效队列。

### 8.4 `shoppingToggleQueue` 存储

键：`[userId, listId, itemId]`

```ts
type OfflineShoppingToggle = {
  userId: string;
  listId: string;
  itemId: string;
  targetChecked: boolean;
  clientMutationId: string;
  queuedAt: string;
  attemptCount: number;
  lastError: string | null;
};
```

相同键再次操作时覆盖 `targetChecked`、`clientMutationId` 和 `queuedAt`，因此队列始终只保留最后目标状态。

## 9. 数据写入与容量控制

- 快照写入只发生在客户端，且使用空闲调度或非阻塞 Effect，不延迟路由响应。
- 每个用户最多保存 10 条菜谱快照。
- 菜谱快照只存结构化文本数据，首版不保存图片 Blob。
- IndexedDB 写入失败不影响在线主流程；显示一次“离线副本保存失败”提示并记录可诊断错误。
- 数据结构包含 `dataVersion`，未来升级时可以迁移或安全丢弃不兼容快照。
- 不使用 `localStorage` 存储私人菜谱或队列。

## 10. 购物清单同步与冲突处理

### 10.1 本地操作

离线勾选时使用一个 IndexedDB 事务同时完成：

1. 更新购物清单快照中的 `isChecked`。
2. 写入或覆盖该条目的队列记录。

UI 立即更新，并为尚未同步的条目显示轻量状态标识。

### 10.2 服务端操作

复用并收紧现有 `setShoppingItemCheckedAction`：

- 服务端重新调用 `auth.getUser()` 获取真实用户。
- 验证清单属于当前用户且仍为活动清单。
- 按 `user_id + shopping_list_id + item_id` 更新目标 `is_checked`。
- 返回服务器确认的 `itemId`、`isChecked` 和 `updatedAt`，而不是只返回 `null`。
- 现有 RLS、复合外键和 `updated_at` 触发器继续提供数据库侧保护。

更新同一个目标布尔值可以安全重试，因此不需要新增数据库 RPC 或迁移。

### 10.3 冲突规则

- 同一设备离线期间：最后一次本地目标状态覆盖之前状态。
- 多设备之间：服务器最后成功接收到的有效更新生效。
- 当前设备同步完成后必须重新读取服务器活动清单，以服务器快照覆盖本地快照。
- 如果条目已删除或活动清单已被替换，同步器先获取最新清单；确认旧操作已无可用目标后删除该失效队列项，并告知用户清单已变化。
- 普通网络错误、5xx 或暂时无法确认的错误不能删除队列。

### 10.4 并发控制

- 同一浏览器标签页只允许一个同步任务运行。
- 使用模块级 Promise/锁合并同时发生的 `online`、页面挂载和用户手动重试。
- 首版顺序同步，优先保证状态可解释；队列规模仅与当前购物清单条目数相关，不需要并行化。

## 11. 登录、退出与隐私

- 在线页面只能使用服务器验证后的 `userId` 写入对应命名空间。
- 离线壳只能读取最后成功认证用户的本机快照，但会明确标注“本机离线副本”，不能据此获得服务器权限。
- 浏览器配置文件本身不等同于加密存储；本功能面向用户自己的受控设备，不宣称抵御拥有设备账户权限的本地攻击者。
- 设置页退出按钮改为客户端协调流程：先删除整个 `ordine-offline-v1` 数据库，再调用现有服务端退出操作。
- 即使服务端退出失败，本地私人快照也必须保持已清除状态。
- 设置页新增“清除离线数据”，只清 IndexedDB 私人数据，不注销账号、不删除服务器数据。
- 不在日志、通知或错误信息中输出菜谱内容、用户 ID、会话或队列完整载荷。

## 12. UI 与状态反馈

### 12.1 全局状态

- 离线：显示“当前离线，正在使用本机副本”。
- 有待同步操作：显示数量，例如“2 项待同步”。
- 同步中：显示非阻塞进度状态。
- 同步完成：显示一次简短成功提示。
- 同步失败：提示保留操作并提供“重新同步”。

### 12.2 离线菜谱

- 菜谱列表只展示已缓存的最近菜谱，并注明“最近离线菜谱”。
- 图片区域使用固定尺寸占位，避免布局跳动。
- 详情和烹饪页保留核心内容、份量换算、步骤切换和本地计时器。
- 编辑、收藏及依赖服务器的按钮禁用或隐藏，并解释需要联网。

### 12.3 离线购物清单

- 允许勾选和取消勾选。
- 每个未同步条目显示轻量状态，不使用持续动画。
- 新增、编辑、删除、排序、清空和重新生成控件禁用，并标注“联网后可用”。

### 12.4 可访问性

- 状态提示使用合适的 `aria-live`，避免每次快速勾选都重复播报整页。
- 离线壳支持键盘操作、可见焦点和至少 44px 移动端触控区域。
- 尊重 `prefers-reduced-motion`。

## 13. 错误处理

| 场景 | 行为 |
| --- | --- |
| IndexedDB 不可用 | 在线功能继续；离线能力显示不可用 |
| 快照写入失败 | 不阻塞页面；提示未保存离线副本 |
| 离线壳无当前用户快照 | 显示没有可用离线数据和重试入口 |
| 会话过期 | 停止同步、保留队列、要求重新登录 |
| 网络中断 | 保留未确认队列，等待下次恢复 |
| 清单已替换 | 获取服务器新清单，清除确认失效的旧队列 |
| 条目已删除 | 获取服务器状态确认后清除该失效操作 |
| Worker 新壳安装失败 | 旧 Worker 和旧壳继续使用，不自动接管 |
| 数据版本不兼容 | 安全清除旧快照并提示需联网重新缓存 |

## 14. 预计涉及文件

具体路径在实施计划中最终确认，预计控制在以下范围：

- `package.json`、锁文件：加入轻量 `idb` 依赖。
- `src/features/offline/**`：类型、IndexedDB 仓库、快照、队列、同步器和 UI 状态。
- `src/app/offline/app/**`：公开离线壳入口。
- `src/features/pwa/service-worker-source.ts`：公开壳精确预缓存与冷启动路由。
- `src/features/pwa/components/pwa-runtime.tsx`：联网恢复同步和状态整合。
- 菜谱详情/烹饪及购物清单客户端边界：写入最新快照。
- `src/features/shopping/actions.ts`：返回服务器确认状态。
- 设置页退出控件：清除私人离线数据。
- 中间件公开路径配置。
- 对应单元测试、组件测试和 PWA 浏览器验收测试。

不计划修改 Supabase migration、表结构、RLS 策略或 Storage 策略。

## 15. 实施顺序

1. 用测试定义 IndexedDB schema、最近 10 条淘汰和用户隔离。
2. 实现菜谱与购物清单在线快照写入。
3. 用测试定义最后状态覆盖、原子更新和队列保留规则。
4. 扩展服务端勾选 Action 的确认结果，并实现同步器。
5. 实现公开离线壳与受支持的冷启动路由。
6. 扩展 Service Worker 的版本化精确壳缓存和更新测试。
7. 实现退出清理、设置页清理入口与全局同步反馈。
8. 完成桌面、360px、390px、430px、安装、离线冷启动和版本更新验收。

## 16. 测试与验收标准

### 16.1 自动化测试

- IndexedDB 数据库升级和不兼容版本处理。
- 不同 `userId` 数据隔离。
- 菜谱最多保留最近 10 条。
- 菜谱快照不包含签名图片 URL、令牌或 Cookie。
- 购物勾选的快照与队列在同一事务内更新。
- 同一条目多次操作只保留最后目标状态。
- 同步成功删除队列并刷新服务器快照。
- 暂时失败保留队列；确认失效后才移除。
- 同步锁避免重复提交。
- 退出登录无论服务端结果如何都清除本地私人数据。
- Service Worker 只缓存公开离线壳精确依赖，不缓存 `/api/`、Supabase、私人页面响应或任意运行时响应。
- 新 Worker waiting、用户确认更新、旧缓存清理和只刷新一次。

### 16.2 浏览器验收

桌面以及 360px、390px、430px 分别验证：

1. 在线打开至少 2 道菜谱和当前购物清单。
2. 完全关闭 PWA，断网后重新启动。
3. 从 `/recipes` 查看离线菜谱列表、详情和分步烹饪。
4. 从 `/shopping` 连续勾选和取消同一条目，确认最终本地状态正确。
5. 恢复网络，确认自动同步且最终服务器状态正确。
6. 同步中再次断网，确认未确认操作仍在。
7. 退出登录，确认 IndexedDB 私人数据和队列清空。
8. 安装新版本但暂不确认更新，确认旧版本继续工作；确认更新后只刷新一次且样式一致。
9. 检查 Cache Storage 中没有私人页面、API、Supabase 响应或用户数据。
10. 检查控制台无错误，页面无横向溢出，滚动和勾选无明显掉帧。

## 17. 完成标准

- 断网冷启动能进入公开离线壳并读取当前用户本机快照。
- 最近 10 条菜谱可离线查看详情和分步烹饪。
- 当前购物清单可离线勾选，最后状态覆盖与恢复同步符合规则。
- 退出登录可清除全部私人离线数据。
- Cache Storage 中没有私人数据和任意运行时页面缓存。
- 新旧 PWA 版本不会混用 HTML、JS 和 CSS。
- 自动化与指定浏览器验收通过。
