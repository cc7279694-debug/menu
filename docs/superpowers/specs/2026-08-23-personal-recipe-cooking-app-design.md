# 食序：个人菜谱与分步烹饪助手设计规格

- 日期：2026-08-23
- 状态：待用户审阅
- 产品工作名：食序
- 技术目录：`recipe-step-app`

## 1. 产品概述

食序是一款面向个人使用的菜谱管理与分步烹饪 PWA。用户可以记录自己的菜谱，把食材与具体步骤关联，在做菜时按大卡片逐步操作，并从一道或多道菜生成可勾选的购物清单。

产品不以内容社区、菜谱推荐或 AI 生成为核心，而是把用户自己的菜谱变成可以直接执行和持续改进的“个人厨房操作手册”。

## 2. 目标与成功标准

### 2.1 MVP 目标

1. 用户可以在手机或电脑上可靠地记录和查找个人菜谱。
2. 用户做菜时不需要在完整食材表和长篇步骤之间反复滚动。
3. 用户可以根据实际人数换算食材，并在步骤中看到当前要用的食材。
4. 用户可以从多道菜生成清晰、可修改、可勾选的购物清单。
5. 厨房或超市网络不稳定时，最近菜谱和当前购物清单仍可使用。

### 2.2 产品成功标准

- 新用户能在 5 分钟内手动录入一道包含图片、食材和步骤的菜谱。
- 用户能在 3 次点击内从菜谱详情进入分步烹饪。
- 烹饪过程中，当前步骤、相关食材、计时器和导航在一个屏幕内完成主要操作。
- 多菜购物清单不会在不确定的情况下错误合并食材。
- 手机端 360px 宽度和常见桌面尺寸均可完整操作。
- 未登录用户无法访问任何私人菜谱、图片或购物清单。

## 3. 用户范围与关键假设

- MVP 只支持个人使用，不包含家庭空间、邀请、成员角色或共享编辑。
- 每位用户使用独立账号，数据可以在手机和电脑间同步。
- 第一版采用手动录入；网页链接、图片、视频和 AI 导入属于后续能力。
- 第一版提供成品封面和每步骤一张图片，不上传视频。
- 菜谱编辑要求联网；最近打开的菜谱和当前购物清单支持有限离线使用。
- 产品采用中文优先的中式做菜表达，同时兼容数字用量与“少许、适量”等经验用量。

## 4. MVP 范围

### 4.1 账号与同步

- 邮箱验证码登录，不维护传统密码。
- 登录状态安全持久化。
- 菜谱、收藏、标签和购物清单跨设备同步。
- 退出登录时清除本机私人离线缓存。

### 4.2 菜谱管理

- 创建、查看、编辑和删除菜谱。
- 菜谱字段包括：菜名、简介、封面、基础份数、准备时间、烹饪时间、分类、标签和个人调整备注。
- 食材包括：名称、数字用量或文字用量、单位、预处理备注及排序。
- 步骤包括：说明、可选图片、可选计时时长、排序及关联食材。
- 支持分类、自定义标签、收藏和关键词搜索。
- 搜索范围至少覆盖菜名、食材名称和标签。
- 删除菜谱前二次确认；MVP 使用软删除或回收站语义，避免误删后立即永久丢失。

### 4.3 份量换算

- 菜谱保存基础份数，例如 2 人份。
- 开始烹饪或加入购物清单前，可选择目标份数。
- 数字用量按 `目标份数 / 基础份数` 等比例换算。
- “少许、适量”等文字用量原样保留。
- 展示结果采用便于阅读的合理精度，避免出现过长小数。

### 4.4 分步烹饪

- 每次展示一个大步骤，支持上一步、下一步和步骤进度。
- 当前步骤同时显示关联食材及换算后的用量。
- 步骤图片可点击放大。
- 一个步骤可以启动计时器，多个步骤计时器可以并行运行。
- 计时器以目标结束时间计算，应用切到后台后仍能恢复准确剩余时间。
- 支持的浏览器中请求屏幕常亮；不支持时给出非阻塞提示。
- 当前烹饪进度优先保存在本机，不频繁写数据库。

### 4.5 购物清单

- 用户可选择一道或多道菜，并分别设置目标份数。
- 生成前允许取消家中已有的食材。
- 自动合并同一标准食材且单位完全兼容的数字用量。
- 单位不兼容、文字用量或判断不确定时保留独立条目，不做猜测性换算。
- 清单条目显示来源菜谱，支持按蔬菜、肉蛋、调味品、主食等采购分组。
- 支持手动添加、编辑、删除、排序和勾选。
- 当前购物清单支持离线查看与勾选，恢复网络后自动同步。

### 4.6 PWA 与适配

- 提供 Manifest、应用图标、主题色和添加到桌面能力。
- 手机端使用底部导航；桌面端使用侧边导航或宽屏布局。
- 最近打开的菜谱快照和当前购物清单存入本地数据库。
- 网络不可用时明确显示离线状态，不伪装保存成功。

## 5. 明确不在 MVP 中的功能

- 家庭共享、邀请和多人协作
- 公开菜谱、关注、点赞、评论和推荐流
- AI 菜谱生成或自动分类
- 网页、短视频、截图、PDF 或 OCR 导入
- 视频上传和播放
- 语音控制、隔空手势和智能穿戴设备
- 周菜单、日历、备餐计划和前置准备提醒
- 食材库存、保质期和条码
- 营养分析、热量和健康建议
- 生鲜电商、配送和智能厨具集成
- 付费会员体系

## 6. 信息架构与页面

### 6.1 主导航

- 菜谱
- 购物
- 收藏
- 设置

搜索入口放在菜谱首页顶部，不单独占用底部导航位置。

### 6.2 页面清单

1. 登录页：邮箱输入、验证码验证和隐私说明。
2. 菜谱首页：最近使用、全部菜谱、分类、标签和新建入口。
3. 搜索结果：按菜名、食材和标签匹配。
4. 菜谱详情：封面、份数、食材、步骤、备注及主要操作。
5. 菜谱编辑：基本信息、食材编辑、步骤编辑和图片上传。
6. 分步烹饪：当前步骤、相关食材、图片、计时和进度。
7. 购物清单生成：选择菜谱、份数和排除已有食材。
8. 当前购物清单：分组条目、来源、勾选和手动编辑。
9. 设置：账号、离线缓存管理和退出登录。

## 7. 核心用户流程

### 7.1 录入菜谱

登录 → 新建菜谱 → 填写基础信息 → 添加食材 → 添加并排序步骤 → 为步骤关联食材 → 上传封面和步骤图片 → 保存 → 查看菜谱详情。

保存时统一校验必要字段。图片先压缩再上传，数据库记录只在媒体上传成功后提交，避免产生引用失效的菜谱。

### 7.2 分步做菜

打开菜谱 → 选择目标份数 → 开始烹饪 → 查看当前步骤和相关食材 → 启动计时器 → 上一步或下一步 → 完成 → 返回菜谱并可更新个人调整备注。

### 7.3 生成购物清单

进入购物页 → 选择多道菜和份数 → 取消已有食材 → 生成清单 → 系统谨慎合并 → 用户复核并修改 → 购物时逐项勾选 → 清除已完成条目。

## 8. 技术架构

### 8.1 固定技术栈

- Next.js 15 App Router
- React + TypeScript
- Tailwind CSS
- shadcn/ui
- Next.js Server Actions；必要时使用 Route Handlers
- Supabase Auth、PostgreSQL、Storage
- Vercel
- PWA Manifest、Service Worker、Cache Storage 与 IndexedDB

不创建单独后端服务。

### 8.2 模块边界

- `auth`：登录、会话、退出和路由保护。
- `recipes`：菜谱查询、编辑、分类、标签和收藏。
- `ingredients`：食材标准化、用量与份数换算。
- `cooking`：步骤展示、步骤食材、计时器、进度和屏幕常亮。
- `shopping`：菜谱选择、食材合并、清单编辑与离线同步。
- `media`：图片压缩、上传、访问和删除。
- `offline`：菜谱快照、本地购物变更队列和网络状态。

每个模块只通过明确的服务接口和类型访问数据，不让页面组件直接拼接复杂数据库操作。

### 8.3 数据流

- 在线读取：Server Component 或受控客户端请求 → Supabase → 类型化视图模型 → UI。
- 在线写入：表单 → Server Action → 输入校验 → 权限校验 → 数据库事务 → 重新验证相关页面。
- 图片：客户端压缩 → 私有 Storage → 保存路径到数据库 → 签名 URL 展示。
- 离线菜谱：在线打开菜谱后写入 IndexedDB 快照；离线只读。
- 离线购物：本地立即更新 → 写入待同步队列 → 恢复网络后幂等提交 → 服务器确认后清除队列。

## 9. 数据库设计

所有主键使用 UUID，时间字段统一使用带时区时间。业务表包含 `created_at` 和 `updated_at`。需要排序的子项使用稳定的 `sort_order`。

### 9.1 用户与分类

#### `profiles`

- `id`：对应 `auth.users.id`
- `display_name`
- `created_at`
- `updated_at`

#### `categories`

- `id`
- `user_id`
- `name`
- `sort_order`

用户内分类名称唯一。

#### `tags`

- `id`
- `user_id`
- `name`

用户内标签名称唯一。

### 9.2 菜谱

#### `recipes`

- `category_id`，可空
- `title`
- `description`，可空
- `cover_path`，可空
- `base_servings`
- `prep_minutes`，可空
- `cook_minutes`，可空
- `personal_notes`，可空
- `is_favorite`
- `deleted_at`，可空
- `created_at`
- `updated_at`

#### `recipe_tags`

- `recipe_id`
- `tag_id`

联合主键避免重复关联。

#### `ingredients`

- `id`
- `user_id`
- `display_name`
- `normalized_name`
- `default_aisle`，可空

`normalized_name` 用于保守匹配；系统不依赖模糊 AI 判断。

#### `recipe_ingredients`

#### `recipe_steps`

该关联让烹饪模式能直接展示当前步骤所需食材；覆盖数量用于“一半先炒、剩余后加”等情况。

### 9.3 购物清单

- `name`
- `is_active`
- `created_at`
- `updated_at`

MVP 界面只突出一个当前清单，数据结构允许未来支持多个清单。

#### `shopping_list_sources`

- `id`
- `shopping_list_id`
- `recipe_id`
- `selected_servings`

#### `shopping_list_items`

- `id`
- `shopping_list_id`
- `ingredient_id`，手动条目可空
- `name_snapshot`
- `quantity`，可空
- `quantity_text`，可空
- `unit`，可空
- `aisle`，可空
- `is_checked`
- `is_manual`
- `sort_order`

#### `shopping_list_item_sources`

- `shopping_list_item_id`
- `shopping_list_source_id`
- `recipe_ingredient_id`

用于显示一个合并条目来自哪些菜谱。

### 9.4 约束与索引

- 所有数量和份数必须大于 0。
- 同一菜谱下步骤和食材排序字段建立组合索引。
- `recipes(user_id, updated_at)`、`recipes(user_id, is_favorite)` 建立索引。
- `ingredients(user_id, normalized_name)` 建立唯一或受控唯一索引。
- 搜索使用 PostgreSQL 可维护的全文或模糊索引方案，MVP 不引入外部搜索服务。
- 清单来源和条目关联均设置合理外键删除策略，避免孤儿记录。

## 10. 安全与隐私

- 所有私人业务表启用 RLS。
- 用户只能访问 `auth.uid()` 所属的数据；子表通过所属菜谱或清单验证所有权。
- Storage 使用私有 Bucket，路径以用户 ID 开头，并配置读取、上传、替换和删除策略。
- 服务端重新校验所有用户输入，不信任客户端传入的 `user_id`。
- 图片限制类型和大小，客户端压缩不能替代服务端校验。
- 不记录邮箱验证码、访问令牌或完整环境变量。
- 登出时清除 IndexedDB 中的私人快照和待同步队列。

## 11. 离线与冲突策略

- 应用壳和静态资源由 Service Worker 缓存。
- 最近打开的有限数量菜谱存入 IndexedDB，仅支持查看与烹饪。
- 当前购物清单存入 IndexedDB，离线可以勾选和取消勾选。
- 离线期间不允许创建、编辑或删除菜谱，避免复杂合并冲突。
- 同一购物条目的离线勾选队列只保留最后目标状态；恢复联网后执行幂等的“设置勾选状态”操作。
- 同一条购物项跨设备冲突时，以服务器接收的最后一次有效变更为准，并刷新本地状态。
- 同步失败保留队列并提示用户，不丢弃本地操作。

## 12. 错误处理

- 表单错误在具体字段旁显示，并保留已填写内容。
- 未保存编辑离开页面前给出提示。
- 图片上传失败允许单独重试，不生成损坏引用。
- 保存操作使用明确的提交状态，避免重复提交。
- 购物清单无法判断合并时保留原条目，并标注来源，不静默猜测。
- 网络离线时显示全局状态和受限功能说明。
- 计时器通知权限被拒绝时仍保留页面内计时与视觉提醒。
- Wake Lock 不支持或被系统释放时不阻断烹饪流程。
- 服务端异常展示可恢复提示，同时保留可安全重试的数据。

## 13. UI 与交互原则

- 整体采用温暖、克制的中性色，食物图片承担主要色彩。
- 厨房模式使用更大字号、更高对比度和更大的触控区域。
- 主要操作每屏只保留一个视觉主按钮。
- 重要状态不能只依靠颜色表达。
- 图片均提供替代文本；表单、弹窗、计时器和导航支持键盘及读屏。
- 动效短而明确，并尊重减少动态效果设置。
- 手机端优先，编辑复杂结构时在桌面端提供更宽布局，但功能保持一致。

### 14.1 单元测试

- 份量换算、分数和小数显示规则。
- 数字用量、文字用量和空单位处理。
- 购物食材的谨慎合并与不合并规则。
- 多计时器基于目标时间的恢复。

### 14.2 集成测试

- 登录和会话保护。
- 菜谱、食材、步骤及步骤食材的事务保存。
- 图片上传失败后的回滚或清理。
- RLS 对跨用户访问的拒绝。
- 私有 Storage 的读取、上传和删除策略。
- 购物清单生成、来源追踪和幂等同步。

### 14.3 端到端测试

- 手机端登录并创建完整菜谱。
- 从 2 人份切换到 4 人份并进入分步烹饪。
- 当前步骤展示正确关联食材。
- 启动多个计时器、切后台后恢复。
- 从多道菜生成清单，排除已有食材并完成勾选。
- 断网后查看最近菜谱和勾选当前购物清单，联网后完成同步。
- 手机、平板和桌面关键页面的响应式与无障碍检查。

### 14.4 发布前检查

- 格式化、类型检查、Lint、单元测试、集成测试和生产构建通过。
- 检查 Git diff，确认没有无关改动和敏感信息。
- 使用非生产 Supabase 项目验证 Auth、Database、Storage 和 RLS。
- 使用 Vercel Preview 验证 PWA 安装、移动端交互和离线流程。
- 未经明确授权，不连接或修改生产数据库，不部署生产环境。

## 15. 模块化交付顺序

### 模块 1：项目基础、登录与导航

建立 Next.js 应用、设计基础、Supabase 登录、受保护布局和响应式导航。

### 模块 2：菜谱管理

完成数据库基础、菜谱 CRUD、分类标签、收藏搜索、食材步骤、步骤关联食材和图片上传。

### 模块 3：分步烹饪

完成份量换算、单步骤模式、当前步骤食材、并行计时、屏幕常亮和本机进度。

### 模块 4：购物清单

完成多菜选择、已有食材排除、谨慎合并、来源追踪、分组和勾选。

### 模块 5：PWA 与离线优化

完成安装能力、离线菜谱、购物变更队列、恢复同步、性能和无障碍验收。

每个独立模块完成后均执行必要测试、整理提交并暂停等待用户验收，不提前开发下一模块。

1. 网页链接与图片导入。
2. AI 辅助整理步骤，但所有结果必须由用户确认后保存。
3. 自动识别步骤中的时间并生成计时器。
4. 语音播报和无接触翻页。
5. 腌制、解冻等前置准备提醒。
6. 烹饪历史、评分和多次调整记录。
7. 周菜单和备餐计划。
8. 家庭共享。

## 17. 竞品启示

- Paprika 验证了个人菜谱、份量换算、计时和购物清单的长期价值。
- SideChef 验证了带步骤媒体、语音与计时的引导式烹饪体验。
- Crouton 验证了简洁视觉、多计时器和无接触操作的吸引力。
- Pestle、菜谱夹等产品表明跨来源导入会成为后续重要能力，但不应阻塞基础流程。
- 国内“做菜谱”验证了卡片式伴做、前置准备提醒和中文厨房场景。
- 用户反馈表明，搜索不准确、食材与步骤分离、购物条目错误合并，都会显著削弱产品可用性。

因此，食序的 MVP 优先保证：可靠手动录入、步骤关联食材、准确份量换算、谨慎购物合并和清晰厨房交互。
